### 1. Scientific Mesh Generation Architecture

#### Direct Heightfield Mapping
Terrain vertices are constructed directly from the real 2D DSM raster $D(y, x)$ generated by the backend:
- For each grid cell $(r, c)$ in the mesh grid of size $W_g \times H_g$:
  $$\text{Spatial } X = \left(\frac{c}{W_g - 1} - 0.5\right) \cdot \text{span}_x$$
  $$\text{Spatial } Z = \left(\frac{r}{H_g - 1} - 0.5\right) \cdot \text{span}_z$$
  $$\text{Vertex } Y = \frac{D[r, c] - D_{\min}}{\Delta D} \cdot H_{\text{scene}} \cdot \text{exaggeration}$$
- `raw_elevations`: Preserves the true, unnormalized DSM elevation $D[r, c]$ in meters (or relative units for rDSM) for point inspection and measurement tools.
- Multi-LOD Support: Multi-resolution assets are generated concurrently:
  - Low LOD: $64 \times 64$
  - Medium LOD: $128 \times 128$
  - High LOD: $192 \times 192$
- **Zero Fake Terrain**: No simplex noise, Perlin noise, fractal displacement, or procedural synthetic geometry exists anywhere in the mesh pipeline.

#### Aspect Ratio Preservation
To eliminate texture stretching or compression:
$$\text{span}_x = 100.0$$
$$\text{span}_z = 100.0 \cdot \frac{H_{\text{orig}}}{W_{\text{orig}}}$$
The 3D plane dimensions match the native aspect ratio of the input imagery to 4 decimal places, preventing geometric distortion.

### 2. RGB Texture & Spatial Alignment

The original aerial/satellite optical imagery is projected directly onto the 3D surface mesh.
- **UV Coordinate Correspondence**:
  - Vertex $(r=0, c=0)$ (top-left / North-West) maps to UV $(u=0.0, v=1.0)$, sampling row 0 of the input texture.
  - Vertex $(r=H_g-1, c=W_g-1)$ (bottom-right / South-East) maps to UV $(u=1.0, v=0.0)$, sampling row $H-1$ of the input texture.
- **Orientation Consistency**:
  - Image row $0 \rightarrow$ DSM row $0 \rightarrow$ Mesh vertex row $0$ (North / $-Z$).
  - Image col $0 \rightarrow$ DSM col $0 \rightarrow$ Mesh vertex col $0$ (West / $-X$).
  - No flipped axes, inverted elevations, or mirror artifacts.

### 3. Supported Modes

The 3D environment supports 5 display modes:

| Mode | Asset / Shader | Description |
| :--- | :--- | :--- |
| **RGB** | `results.assets.rgb_texture` | Original aerial/satellite orthophoto projected onto the terrain surface. |
| **Elevation** | `results.assets.dsm_color` | Hypsometric color-ramp visualization representing surface elevation from minimum to maximum relief. |
| **Slope** | `results.assets.slope` | $3 \times 3$ finite-difference topographic slope gradient map. |
| **Hillshade** | `results.assets.hillshade` | Analytical shaded relief illuminated with $315^\circ$ azimuth and $45^\circ$ solar elevation. |
| **Wireframe** | Untextured shader material | High-contrast cyan geometric wireframe showcasing the actual triangulated surface facets. |

In addition to pure modes, the Wireframe overlay can be toggled on top of any texture mode.

### 4. Interactive Controls

The 3D environment implements 8 interaction controls:

1. **Orbit**: Orbit controls with smooth damping ($0.05$), bounded polar inclination, and adaptive distance clamping ($10$ to $350$ units).
2. **Fly**: Full WASD/Arrow navigation with mouse-drag look:
   - `W` / `S`: Move forward / backward along camera look vector
   - `A` / `D`: Strafe left / right
   - `Space` / `E`: Ascend vertically
   - `Shift` / `Q`: Descend vertically
   - Mouse drag: Rotates camera yaw and pitch
3. **Top Down**: Nadir orthogonal/top-down perspective with camera at $[0, 140, 0.1]$ pointing straight down at $[0, 0, 0]$, with rotation locked for planimetric analysis.
4. **Point Inspection**: Live hover and pinned click inspection providing pixel coordinates, real DSM predicted height, reference DEM elevation (if available), elevation error (if available), and surface slope.
5. **Distance**: Real-world horizontal ground distance and 3D Euclidean distance between two clicked points, computed using true metric pixel resolution when georeferenced.
6. **Delta-Z ($\Delta Z$)**: Vertical elevation difference $|\Delta Z| = |Z_B - Z_A|$ and slope gradient angle between two selected points.
7. **Reset**: Instant camera re-centering and restoration to default orbit perspective.
8. **Fullscreen**: Native browser fullscreen toggle for distraction-free terrain analysis.

#### Strict Ground Truth Policy
- If reference ground truth is present (e.g. from reference DEM or benchmark dataset):
  - `reference_height`: sampled directly from the reprojected reference DEM array.
  - `error`: computed as $Z_{\text{predicted}} - Z_{\text{reference}}$.
- If unreferenced or uncalibrated:
  - `reference_height`: displays strictly `"Unavailable"`.
  - `error`: displays strictly `"Unavailable"`.
- Reference elevations and errors are **never fabricated, simulated, or zeroed out**.

### 6. Programmatic Scientific Check

To prove that the 3D viewer is driven by the actual scientific DSM and not a mock/procedural model, we execute an automated scientific check:

1. **Baseline State**: Generate 3D heightfield from a base DSM raster with elevation $500.0\text{ m}$. Query vertex at coordinate $(r=20, c=30)$; baseline elevation is $500.0\text{ m}$.
2. **Programmatic Mutation**: Inject a $+50.0\text{ m}$ elevation spike into the DSM array at $(r=20, c=30)$:
   $$D_{\text{modified}}[20, 30] = D_{\text{base}}[20, 30] + 50.0 = 550.0\text{ m}$$
3. **Re-generation**: Re-run `MeshService.generate_mesh_assets` on $D_{\text{modified}}$.
4. **Verification**:
   - The terrain vertex at index $(20 \times 64 + 30)$ in `heightfield.json` and the Wavefront OBJ changes by exactly $\Delta Z = +50.0\text{ m}$.
   - Distant vertices (e.g. $(r=5, c=5)$) remain strictly unchanged ($\Delta Z = 0.0\text{ m}$).
5. **Conclusion**: Proves unequivocally that every vertex in the 3D environment responds directly and deterministically to the underlying scientific DSM.
